# Claude Rules 仕様

## CLAUDE.md と .claude/rules/ の使い分け

| ファイル | 用途 | 対象読者 |
|---------|------|---------|
| `CLAUDE.md` | プロジェクト概要・技術スタック・開発ルールの全体像 | 人間 + Claude |
| `.claude/rules/*.md` | 具体的な命令・制約・判断基準（機械可読） | 主に Claude |

CLAUDE.md は「プロジェクトへの入口」として人間が読む。rules/ は Claude が実行時に参照する命令集。

## 推奨ファイル名パターン

| ファイル名 | 対象ルール |
|-----------|-----------|
| `git-workflow.md` | コミット・ブランチ・PR の規約 |
| `testing.md` | テストの書き方・カバレッジ方針 |
| `error-handling.md` | エラー処理パターン・例外設計 |
| `api-design.md` | エンドポイント命名・レスポンス形式 |
| `security.md` | 機密情報の扱い・認証方針 |
| `dependencies.md` | パッケージ選定基準・バージョン管理 |

## ルールの書き方

```markdown
# <トピック>

- <動作>こと。
- <禁止事項>しないこと。理由: <Why not>
- <条件>の場合は<動作>すること。
```

命令形で書く。理由（Why not）がある場合は末尾に添える。
How（手順）は書かない — コードやスキルに書く。
