# Claude Code 活用リファレンス

## Plan Mode

複雑なタスクは実装前にプランを立てる。「良いプランがあれば実装は1-shotで決まる」が基本姿勢。

```
/plan   # プランモードに入る
```

### いつプランに戻るか

実装中に詰まったら、押し進めるより Plan Mode に戻る方が速い。目安：
- 想定外のファイルが多数関係してきた
- 方針が変わりそう・変わった
- エラーが解決できず3回ループしている

### プランの検証にも使う

実装だけでなく「テスト計画をプランで立てて」「検証ステップを設計して」とプランを求めると、見落としを防げる。

## 並列ツール実行

独立した操作は同じメッセージで依頼すると並列実行される。

```
# 良い例: 1メッセージで依頼
「package.json と tsconfig.json を読んで、依存関係と型設定を確認して」

# 悪い例: 逐次依頼（時間がかかる）
「package.json を読んで」→「次に tsconfig.json を読んで」
```

### git worktree で独立した作業空間を作る

機能開発とバグ修正を並行する場合は worktree を活用する：

```bash
git worktree add ../reversi-feature feature-branch
# ../reversi-feature で独立した Claude セッションを走らせる
```

## サブエージェント活用

広範な調査や長い出力は Agent ツールに委譲して、メインのコンテキストを綺麗に保つ。

### エージェントの種別と使い分け

| エージェント | 使いどき |
|------------|---------|
| `Explore` | ファイル検索・シンボル探索・パターン調査（読み取り専用） |
| `Plan` | 実装方針の設計・トレードオフの評価 |
| `general-purpose` | 複数ファイルにまたがる調査・実装 |

### 効果的なケース

- 「どのファイルで X が定義されているか」を広く探す
- 複数の独立した調査を同時進行させる（並列 Agent 呼び出し）
- テスト結果・ビルドログの要約

## 検証ループ（最重要）

Claude に検証手段を与えることで品質が大きく上がる。型チェック・lint・テストの結果を渡すだけでよい。

### このプロジェクトの検証コマンド

```bash
npm run type-check      # TypeScript 型チェック
npm run lint            # ESLint
npm run test:unit       # ユニットテスト
npm run test:integration # インテグレーションテスト
npm run test:coverage   # カバレッジ確認
npm run build           # ビルド（型エラーも検出）
```

### 検証を Claude に渡すパターン

```
# バックグラウンドで検証させる
「実装が完了したら npm run type-check && npm run test:unit を実行して結果を教えて」

# 自己検証を求める
「この変更で既存テストが壊れていないことを確認してから完了を報告して」
```

## コンテキスト管理

- `/clear` で会話履歴をリセットして新しいタスクを新鮮なコンテキストで始める
- `/compact` はコンテキストが50%に達したころに使う（それ以前は情報ロスの可能性）
- CLAUDE.md に繰り返し伝える情報を書いておくと毎回説明せずに済む

---

## CLAUDE.md の育て方

間違いが起きたときは即座に記録して再発を防ぐ：

```
「さっきの間違いを繰り返さないよう CLAUDE.md を更新して」
```

Claude は自己改善ルールの記述が得意。気づいた規約はそのセッション中に永続化する。
このプロジェクトでは `/update-rules` でルールファイルへの永続化ができる。

## フック活用

### PostToolUse フック（自動フォーマット）

Write/Edit のたびに自動で lint --fix を走らせることで、手動フォーマットの手間をなくせる。
`settings.json` の `hooks.PostToolUse` に設定する。

### ターン終了フック

Claude の応答後に自動で処理を走らせたい場合（例: 通知）も hooks で設定可能。

---

## 権限管理

- よく使うコマンドは `/permissions` で事前許可しておくと承認プロンプトが減る
- `.claude/settings.json` に書いてプロジェクトで共有する
- `--dangerously-skip-permissions` は使わない（セキュリティリスク）
