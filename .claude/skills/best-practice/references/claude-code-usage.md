# Claude Code 活用 Tips

## Plan Mode

複雑なタスクは実装前に `/plan` でプランを立てる。
実装中に方針が変わっても、プランファイルを更新して再承認を得ることで手戻りを最小化できる。

```
/plan   # プランモードに入る（実装前の設計・調査）
```

## 並列ツール実行

独立した操作は同じメッセージでまとめて依頼すると並列実行される。

```
# 良い例: 1メッセージで依頼
「package.json と tsconfig.json を読んで、依存関係と型設定を確認して」

# 悪い例: 逐次依頼（時間がかかる）
「package.json を読んで」→ 「次に tsconfig.json を読んで」
```

## サブエージェント活用

広範なコードベース探索や長い調査は `Agent` ツールに委譲する。
メインのコンテキストウィンドウを汚染せずに、並行して複数の調査を走らせられる。

有効なケース:
- 「どのファイルで X が定義されているか」を広く探す
- 複数の独立した調査を同時進行させる
- 長い出力（テスト結果・ビルドログ）を要約させる

## コンテキスト管理

- `/clear` で会話履歴をリセットし、新しいタスクを新鮮なコンテキストで始める
- 長いセッションでは `/compact` でコンテキストを圧縮する
- CLAUDE.md に繰り返し伝える情報を書いておくと毎回説明せずに済む

## スキル活用

`/setup-linter`・`/setup-cicd` のようなスキルは定型作業を自動化する。
セッション中に学んだ規約は `/update-rules` でルールファイルに永続化する。

## 効果的なプロンプト

- 「〜して」より「〜したい。制約: 既存のパターンに合わせること」のように制約を添える
- 「バグを直して」より「X をすると Y になる。期待は Z」と症状・期待値を明示する
- 大きなタスクは「まず現状を調査して、方針を提案して」と段階を分ける
