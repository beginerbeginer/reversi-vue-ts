# 新機能追加の標準フロー

CLAUDE.md のルールに従い、issue 作成からマージまでを一貫して進めてください。

## 絶対に守ること

**ファイルを変更する前に、必ず GitHub issue を作成する。**
issue 番号が確定するまでブランチを切らない。コードを書かない。

---

## 作業手順

### 1. issue を作成する

```bash
gh ic
```

- タイトル: 実装する機能を端的に（例: `ゲームオーバー検出を追加する`）
- ラベル: 該当するものを付与（新規ツール導入の場合は `tool:<名前>` も作成）
- 作成後、**issue 番号を必ず控える**

### 2. ブランチを切る

```bash
git checkout -b chore/N-説明
```

命名規則: `chore/N-説明`（N は issue 番号、説明は kebab-case）
例: `chore/25-game-over-detection`

### 3. TDD で実装する（`/tdd` スキルに従う）

Red → Green → Refactor のリズムを厳守する。

```
Red   → 失敗するテストを 1 つだけ書く
Green → テストを通す最小限のコードを書く
Refactor → テストが通ったままコードを整理する
```

コンポーネント設計ルールを守る（`/vue-component-rules` 参照）。

### 4. コミットする

コミット前に `/git-secret-guard` でチェックする。

コミットメッセージは **Why（なぜ）** を日本語で書く：

```
変更の要約（1行）

変更した理由・背景。何が問題でなぜこの変更が必要だったか。
How はコードを見ればわかるので書かない。
```

### 5. PR を作成する

```bash
gh pc --title "..." --body "closes #N" --label "..."
```

- タイトル: 70 文字以内
- body に `closes #N` を含める（マージ時に issue が自動クローズされる）
- 新規ツール導入の場合は body に動作確認チェックリストを記載する

### 6. CI が通ることを確認する

PR コメントの CI テーブルで `✅ All checks passed` を確認してからマージする。

### 6.5. ローカルで動作確認する（マージ前に必須）

```bash
npm run dev
```

ブラウザで以下を確認してからマージする：

- [ ] 実装した機能のゴールデンパス（正常系）が動く
- [ ] 既存の機能がリグレッションしていない（石を置く・ターン交代・スコア表示など）
- [ ] エッジケース（パス・ゲームオーバーなど）が想定通り動く

UI や画面の動作はテストでは検証できないため、目視確認を必ずここで行う。
確認できたら `Ctrl+C` でサーバーを停止してマージへ進む。

### 7. マージしてブランチを削除する

```bash
gh pm N
```

### 8. main を最新化する

```bash
git checkout main && git pull
```

---

## 実装ルールまとめ

| 場所 | 書くこと |
|------|--------|
| コード | How（どう実現するか） |
| テストコード | What（何をテストするか・仕様） |
| コミットログ | Why（なぜこの変更が必要か） |
| コードコメント | Why not（なぜその選択か・他の選択肢を排除した理由） |

---

## このセッションでの進め方

まず「何を実装するか」を確認してから issue 作成に進んでください。
